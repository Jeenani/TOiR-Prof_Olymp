# План презентации и защиты проекта АИС «ТОиР-Проф»

## Слайд 1. Проблемная область и актуальность
- Проблема производственных предприятий: внеплановые простои станков, бумажные журналы заявок, несинхронизированные остатки запчастей на разных складах, отсутствие контроля сроков ППР.
- Потери: до 15–25% рабочего времени оборудования тратится на неплановые ремонты и ожидание деталей.
- Цель: единая цифровая платформа «ТОиР-Проф» для оперативного учёта, планирования ППР и аналитики простоев.

## Слайд 2. Целевое решение и функциональные контуры
- **Учётно-справочный контур:** паспорта оборудования (производители, модели), цехи, мобильные бригады, склады и поставщики.
- **Операционный контур:** жизненный цикл заявок (`создана -> назначена -> в работе -> выполнена -> закрыта`), автоматический расчёт простоя, контроль занятости бригад, списание материалов.
- **Аналитический контур:** KPI-дашборд (6 метрик), динамика простоев, топ-5 проблемных узлов, выполнение графика ТО, экспорт в PDF и Excel.
- **Роли:** Администратор, Главный инженер, Мастер цеха, Бригадир.

## Слайд 3. Трёхзвенная архитектура и база данных (3НФ, 22 таблицы)
- **Схема:** Клиенты (Avalonia Desktop + Vue 3 SPA) ──REST/JSON + JWT──▶ ASP.NET Core 10 Web API ──EF Core──▶ PostgreSQL 18.
- **База данных (строгая 3НФ, 22 таблицы):**
  - Выделены `manufacturers` + `equipment_models`, `suppliers`, `team_workshops` (M:N для мобильных бригад), `warehouse_materials` (M:N для хранения одного материала на нескольких складах).
  - Целостность: `UNIQUE`, `CHECK` (хронология дат и ENUM-статусы), `ON DELETE RESTRICT / CASCADE`.
  - Автоматика в БД: 2 триггера (запрет смены статуса списанного станка, проверка дат заявок) и 3 хранимые функции/процедуры (`calculate_downtime`, `get_next_maintenance_date`, `generate_workshop_report`).

## Слайд 4. REST API, Desktop и Web-клиенты
- **REST API:** 31 эндпоинт в Swagger/OpenAPI, JWT-авторизация, RBAC, корректные HTTP-коды (`200/201/400/401/403/404/409/500`).
- **Desktop-клиент (Avalonia UI 11, нативный, без WebView):**
  - Работает строго через REST API; автоблокировка через 15 сек бездействия; офлайн-черновики с автоотправкой; журнал `errors.log`; шаблоны и экспорт PDF (QuestPDF) / XLSX (ClosedXML).
- **Web-клиент (Vue 3 SPA):**
  - Адаптивный интерфейс (1024..1920+), интерактивные графики Chart.js с drill-down, 60-сек автообновление, уведомления и аналитика.

## Слайд 5. Тестирование, документирование и планы развития
- **Модульное тестирование (`ToirProf.Tests`, xUnit):** 16 изолированных тестов по паттерну AAA (расчёт простоя, валидация заявок, расчёт стоимости материалов — 100% прохождение).
- **Интеграционные тесты API (`test_api.py`):** 9/9 проверок Swagger, JWT, БД-выборок.
- **Документация:** `openapi.yaml` + `API_REFERENCE.md`, `DEPLOYMENT_GUIDE.md`, `USER_MANUAL.md`, UML/ERD-диаграммы.
- **Планы развития:** интеграция с IoT-датчиками вибрации/температуры (MQTT -> автоматическое создание аварийной заявки), мобильное приложение обходчика со сканером QR-кодов.
